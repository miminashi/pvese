### Task C: RAID10 commit ⚠️ BLOCKED — 重大な実機挙動を発見

RAID10 commit 着手前に、 Create VD form 内の cursor 位置確定で重大な問題が発覚:

#### 発見 1: `detect_active_cursor_row` の form 内誤検出

実画像 probe (`tmp/pb20517/probe_popup.py`) で:
- `b_popup.png` (実機で popup が Select Drives From として開いた = cursor on y=147 確定):
  - cluster y=121..132 center=126 max=110  ← detect が picking
  - cluster y=349..360 etc — popup overlay
- `a_to_raid_level_03.png` (cursor 想定 on Select RAID Level y=128):
  - cluster y=121..132 center=126 max=110  ← 上と同じ cluster

つまり **`[RAID0]` 値表示の bright cluster (y=121..132, max=110)** は cursor 位置に関わらず常に存在、 detect_active_cursor_row が **常にこれを brightest として picking** してしまう。 form 内 cursor 位置の検出は highlight 単独では不可能。

#### 発見 2: ArrowDown 1 で 2 行飛び (Select RAID Level スキップ)

`tmp/iter/iter_08_v3.py` (NumpadAdd 動作確認):
- form 開いた直後 cursor on Save Config TOP (y=88, size=22065)
- ArrowDown 1 + NumpadAdd 1 → 画像 `b4_numpad_add.png` で **Select Drives From [Free Capacity]** + **Select Drive Groups** 項目名変化 → cursor が y=147 (Select Drives From) にあった

これは Aptio が **Save Config TOP → Select Drives From** に直接ジャンプ (Protect Virtual Drive + Select RAID Level の 2 行をスキップ) する挙動。 Select RAID Level (y=128) は ArrowDown では訪問されない可能性 — もしくは form 初期 cursor の特殊位置から (要追加検証)。

#### 発見 3: NumpadAdd のみが Aptio に届く

`tmp/iter/iter_08_v3.py` で 5 つの `+` 送信方法を試行:
| 方法 | 結果 |
|------|------|
| `vp.keyboard.press("+")` | **届かず** (size 不変) |
| chord `Shift+Equal` (down/press/up) | **届かず** |
| `vp.keyboard.type("+")` | **届かず** |
| `vp.keyboard.press("NumpadAdd")` | **届く** ✓ (size 変化) |
| JS dispatch keypress | **届かず** |

`+/-` 値変更は **NumpadAdd / NumpadSubtract** 必須。 通常の `+` キー event は Aptio (iRMC KVM) で fall through。

#### 発見 4: 画面表示と Aptio 内部状態のずれ

`tmp/iter/iter_08_p4_retry.py` で:
- `nav_to(128, settle_ms=3000)` → reach + settle で y=128 確認
- pre-enter 追加 2s wait → y=128 確認
- Enter → 開いた popup は **Select Drives From のもの** (RAID Level popup ではない)

→ Aptio 内部 cursor は実は y=147 (Select Drives From) にあったが、 iRMC KVM frame buffer が前の y=128 ハイライト状態 (= 誤検出された [RAID0] cluster) を表示。 `settle_ms` を 3000ms に伸ばしても解消せず。

#### 発見 5: ArrowUp from y=88 → wrap to y=411 (Emulation Type)

`tmp/iter/iter_08_v6.py`:
- form_open (cursor y=88) → ArrowUp 1 → cursor y=411 (Emulation Type, form 最下行)
- Emulation Type で NumpadAdd → size 変化 (Default → 別値)
- ArrowDown 1 (from y=411) → cursor y=88 (wrap to TOP)

→ form 内 ArrowUp/Down は wrap-around する。 ただし from-TOP ArrowDown は **2 行飛び**、 from-bottom ArrowUp は **wrap to TOP**。 挙動が一様でない。

## 未完了 / 次セッション課題

### 1. cursor 位置の信頼性ある検出手段の確立 (最優先)

`detect_active_cursor_row` の form 内誤検出問題により、 現状 cursor 位置は **「NumpadAdd を 1 回押して何の値が変わったか」を screenshot size + 画像比較で同定する** しか確実な方法がない。

**提案案**:
- `identify_form_cursor_by_probe(vp, sdir)` 関数を実装:
  1. 現在の screenshot を撮る (`before.png`)
  2. NumpadAdd を 1 回押す → 2s wait → `after.png`
  3. before/after の image diff (pixel-level) で「変化があった y 範囲」 を検出
  4. その y 範囲が cursor の現在行
  5. NumpadSubtract を 1 回押して値を元に戻す (副作用 cleanup)
- もしくは、 fingerprint DB に form の各 cursor 位置の size を登録 (RAID0 default の 12 navigable items)、 size identify で cursor を確定

### 2. Select RAID Level (y=128) に到達する手段

ArrowDown では skip される。 候補:
- **form 初期 cursor が y=128 にいる**: form 開いた直後 NumpadAdd でなにが変わるか確認
- **Tab / Shift+Tab で項目間 cycle** (Aptio で動作する? 未検証)
- **Select RAID Level に Enter で submenu (popup) を開く**: 本来の Aptio 仕様。 ただし「+/-」 で値変更可能なら popup 不要

### 3. drives popup の cursor 検出

popup overlay は画面の中央右付近 (x≈410-580, y≈350-420)。 popup 内 cursor detection は `detect_active_cursor_row` の x/y 範囲を popup 領域に限定すれば動作する見込み (要実機検証)。
