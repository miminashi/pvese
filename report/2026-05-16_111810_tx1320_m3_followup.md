## 実施内容と結果

### Phase A: `scripts/irmc-virtualmedia.sh` 新規 (完了)

Redfish OEM `/redfish/v1/Systems/0/Oem/ts_fujitsu/VirtualMedia` を PATCH して SMB CDImage を設定するシェルスクリプト。サブコマンド: `status` / `config` / `mount` / `umount` / `verify`。

**新発見** (実装中に判明、scripts/irmc-virtualmedia.sh および memory に記録済み):

- **OEM Redfish PATCH に If-Match ヘッダ必須**: 標準 Redfish のオプションだが Fujitsu OEM は強制 (HTTP 412 PreconditionFailed)
- **iRMC は If-Match を `quotes なし` で要求**: 標準 `If-Match: "1778128217"` は 412 になる。`If-Match: 1778128217` (bare) でないと通らない。スクリプトは ETag を HTTP ヘッダから取得し quotes なしで送信

検証:
```sh
$ ./scripts/irmc-virtualmedia.sh status 10.254.254.9 claude Claude123
CDImage.Server=
CDImage.ShareName=
CDImage.ImageName=
RemoteMountEnabled=true

$ ./oplog.sh ./scripts/irmc-virtualmedia.sh umount 10.254.254.9 claude Claude123
PATCH payload: {"CDImage":{...空...},...}
{...success...}
HTTP 200
```

実機 SMB マウント (`config` / `mount`) は、SMB share `10.1.6.1:/public` が別拠点 (training-tx1320) から到達可能かが未確認のため、本セッションでは PATCH の動作確認まで。

### Phase B/C: `scripts/irmc-kvm-screenshot.py` / `irmc-kvm-interact.py` 新規 (完了)

iRMC S4 HTML5 KVM (AVR; Advanced Video Redirection) を Playwright で自動操作。Tier 1 (screenshot) と Tier 2 (キー送信) を実装。

**iRMC Web UI / KVM プロトコル解析結果**:

- Web UI は HTML 4 + IE8 互換、`<form action="/login">` で submit button は `P99` (hidden `APPLY=99`、Basic Auth はパスワード渡しに使用)
- **iRMC は SID を Cookie ではなく URL パラメータで保持**: ログイン後の URL に `?sid=<SID>` が付与され、以降全リンクに引き継がれる
- HTML5 KVM viewer URL: `https://<bmc>/viewer.html?sid=<SID>` (Server Management ページ `/25?ms=0` の "Video Redirection (HTML5)" リンク先)
- WebSocket: `wss://<bmc>/kvm` (proprietary protocol, viewer.min.js 経由)
- canvas selector: `#kvm` (800x600 fixed)、`canvas.classList.contains('alive')` で接続成立判定
- Playwright headless Chromium で動作確認: ログイン → SID 抽出 → viewer.html → canvas.toDataURL → PNG 保存

**実機動作確認**:

```sh
$ .venv/bin/python scripts/irmc-kvm-screenshot.py \
```

サブコマンド: `screenshot` / `sendkeys` / `type` / `hold` / `combo` / `shell` (複数 step を 1 viewer session で実施)。

**実装課題** (引き継ぎ事項に記載):

- **canvas frame refresh 問題**: 新規 viewer session を開くと、サーバが差分しか送らないため static screen (BIOS Setup 中) では canvas が真っ白/真っ黒。**何か key を送ると full frame を送ってくる** (`Control` 単独で観測)。
- 連続操作時は **1 viewer session 内で全 step を完結させる** (`shell` サブコマンド推奨)
- 連続キー送信時は各 screenshot 前に `Control` を送ると確実 (frame refresh 誘発)

### Phase D: RAID10 構成 (部分実装、自動化は時間切れで手動依頼に切替)

KVM 自動操作 (Phase B/C) で BIOS Setup に到達できることは確認済み (`kvm-after-enter.png` 添付)。ただし以下の理由で本セッション内の自動 RAID10 構成は **見送り**:

1. **frame refresh の挙動** (上記): 1 session 内なら大丈夫だが、BIOS RAID Configuration Utility の menu structure 把握に追加調査が必要
2. **iRMC Web UI Storage タブの位置不明**: System Components (`/8?ms=1`) や Network Inventory (`/79?ms=1`) には RAID/Storage 情報が出ない。BIOS サブメニュー (`/14?ms=2`) には Backup/Restoration と BIOS Update のみ。RAID コントローラ Model は BIOS Setup の Advanced タブ内、または OS 起動後の `dmesg | grep -i mega` で確認するしかない
3. **PRIMERGY TX1320 M3 の onboard RAID コントローラの Model 未確定**: PRAID EP400i / EP420i / CP400i のいずれかと推定 (eLCM なしのため Redfish からは取れない)

**手動依頼**: 引き継ぎ事項を参照。skill `irmc-bios-raid` の `raid create-r10` 手順に従い、`viewer.html` をブラウザで開いて手動操作するか、本セッションで実装した `irmc-kvm-interact.py shell` で半自動化する。

### bmc-power.sh の iRMC 拡張 (新規)

実機検証で発覚した iRMC 固有挙動への対応:

1. **`ResetType` AllowableValues が PowerState で動的に変わる** (前セッションの reference.md が誤り):
   - PowerState=`Off` → `["On"]` のみ
   - PowerState=`On` → `["ForceOff", "ForceRestart", "Nmi", "PushPowerButton"]`
   - **Off→On 遷移には `"On"` を使う** (default で OK)。`PushPowerButton` は On 状態での pulse 用途のみ
   - 修正: `POWER_ON_RESET_TYPE` のデフォルトは元から `On` (修正不要)。memory/reference.md/CLAUDE.md/README.md の説明を `PushPowerButton` → `On` に訂正
2. **PATCH に If-Match (quotes なし) 必須**:
   - 新環境変数 `BMC_PATCH_REQUIRES_ETAG=1` を導入。`redfish_patch()` で GET → ETag 取得 → `If-Match: <etag>` (quotes なし) を付けて PATCH
3. **`BootSourceOverrideEnabled` AllowableValues に `Disabled` がない**:
   - iRMC は `["Once", "Continuous"]` のみ。`boot-override-reset` で `Disabled` を送ると 412
   - 新環境変数 `BMC_BOOT_OVERRIDE_NO_DISABLED=1` を導入。reset 時は `BootSourceOverrideTarget: None` + `BootSourceOverrideEnabled: Once` を送り、override を実質キャンセル

config/training_tx1320.yml に対応する `bmc_patch_requires_etag: "1"` と `bmc_boot_override_no_disabled: "1"` を追加。

検証:
```sh
$ BMC_SCHEME=https BMC_CURL_OPTS='--ciphers DEFAULT@SECLEVEL=0' POWER_ON_RESET_TYPE=On \
    ./oplog.sh ./scripts/bmc-power.sh cycle 10.254.254.9 claude Claude123 20
ForceOff... → Waiting 20s... → Power On... → Power cycle complete (ResetType=On)

$ BMC_SCHEME=https BMC_CURL_OPTS='--ciphers DEFAULT@SECLEVEL=0' BMC_PATCH_REQUIRES_ETAG=1 \
    ./scripts/bmc-power.sh boot-override 10.254.254.9 claude Claude123 Cd UEFI
{..."BootSourceOverrideTarget":"Cd","BootSourceOverrideEnabled":"Once","BootSourceOverrideMode":"UEFI"...}
HTTP 200 → Boot override set: target=Cd mode=UEFI (once)

$ BMC_SCHEME=https BMC_CURL_OPTS='--ciphers DEFAULT@SECLEVEL=0' BMC_PATCH_REQUIRES_ETAG=1 BMC_BOOT_OVERRIDE_NO_DISABLED=1 \
    ./scripts/bmc-power.sh boot-override-reset 10.254.254.9 claude Claude123
{..."BootSourceOverrideTarget":"None","BootSourceOverrideEnabled":"Once"...} → Boot override disabled
```

既存機種 (Supermicro/iDRAC) の挙動は環境変数未設定で従来どおり (デフォルト維持)。
