## 7. fsinfo_unix_valid_level の実装 (smb2_trans2.c lines 2018-2033)

static bool fsinfo_unix_valid_level(connection_struct *conn,
				    uint16_t info_level)
{
	if (conn->sconn->using_smb2 &&
			lp_smb3_unix_extensions() &&
			info_level == SMB2_FS_POSIX_INFORMATION_INTERNAL) {
		return true;
	}
#if defined(SMB1SERVER)             ← ★★★ TYPO BUG ★★★
	if (lp_smb1_unix_extensions() &&
			info_level == SMB_QUERY_POSIX_FS_INFO) {
		return true;
	}
#endif
	return false;
}

★ Samba ビルドは WITH_SMB1SERVER (with WITH_ prefix) を define する
★ SMB1SERVER (without WITH_) は何処にも define されていない

## 10. 結論

(a) Samba 4.19.5 の source3/smbd/smb2_trans2.c:2026 に typo bug:
    #if defined(SMB1SERVER)  → 正: #if defined(WITH_SMB1SERVER)

(b) この typo により fsinfo_unix_valid_level は SMB1 SMB_QUERY_POSIX_FS_INFO に対して
    永久に false を返し、smbd_do_qfsinfo は NT_STATUS_INVALID_LEVEL を返す

(c) iRMC FW 9.08F は qfsinfo level=513 (POSIX_FS_INFO) を要求し、
    INVALID_LEVEL を受けると USB device 生成段階で abort する (60s retry 継続)

(d) 修正は 1 文字追加 (SMB1SERVER → WITH_SMB1SERVER) のみで完了する見込み
