`irmc-bios-raid` スキルを堅牢化するため、training-tx1320 (Fujitsu iRMC S4 FW 9.69F) の
BIOS メニュー (AVAGO MegaRAID HII) 経由で RAID0 の削除→再作成を反復する。

- 前セッション (cosmic-aho / report 2026-06-01_065958) で削除→再作成は **2回成功** (手動協調1回 + 完全自動1回)、
  確認ダイアログ自動操作レシピも確立済。しかし当初指示の反復回数 (10回→ユーザが3回に削減) は**未完遂**。
- 自律ループ `cycle_runner.py` は caret_y=393 を盲信して Enter する欠陥で **Intel NIC 設定画面へ誤入** し頓挫
  (report の「🚨 訂正」節)。教訓 = **per-key 手動 careful が唯一安定**、Enter 前に必ず画面の文字を読む。
- 本セッションのゴール: **per-key 手動で 3 サイクル完走**し、各サイクルを OEM 真VGA で裏取り。
  検証中に**実際に機能したツールだけ** `scripts/` + スキルへ昇格する (機能しなかったもの・欠陥ある
  `cycle_runner.py` は見送り)。

## 鉄則 (前回の失敗から / SKILL.md・NOTES.md より)
1. **🚨 サブメニュー/ユーティリティに入る前に画面の文字 (行テキスト + 右ヘルプ) を必ず読んでから Enter**。
2. **1キー送信ごとに screenshot を読んでから次キーを決める**。バッチ送信厳禁。
3. **成功は OEM 真VGA (`snap.sh`) で VD 行を裏取りしてから判定**。
4. **並列 Bash 呼び出しを避ける** (pkill exit1 連鎖キャンセル + 複数 KVM サーバ競合)。逐次実行。
5. **F1 を制御テストに使わない**。BIOS 最上位タブで **Esc を押さない**。確認ダイアログの ► は静的表示。
6. **KVM master は単一セッション保持**。劣化したら復旧フロー。
7. **状態変更操作は `./oplog.sh` でログ記録**。一時ファイルは `tmp/<sid>/`。
