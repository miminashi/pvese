# 10号機 (Supermicro X10DRT-P) サーバ追加レポート

- **実施日時**: 2026年4月30日 02:31 JST

## 添付ファイル

- [実装プラン](attachment/2026-04-30_023103_add_server10_x10drt_p/plan.md)

## 前提・目的

- 背景: 既存の 4-9号機に加えて、新規物理サーバ 1 台 (Supermicro X10DRT-P, BMC `10.10.10.30`) を pvese プロジェクトの操作対象に追加する必要が生じた
- 目的: 既存の `os-setup` スキル (`bmc_type: supermicro` の Platform Dispatch) から新サーバが操作できるよう、設定ファイルとドキュメントを整備する
- 範囲: config/ドキュメント整備のみ。OS インストール、LINSTOR/IB 設定、BIOS 検証は本作業のスコープ外
- ユーザ確認済みの方針:
  - ホスト名 `ayase-web-service-10`、静的IP `10.10.10.210`
  - LINSTOR 未参加 (実機・IB 確認後に別タスクで決定)
  - `bios-setup` スキルの X10DRT-P 対応は今回触らない

## 環境情報

| サーバ | BMC IP | 静的 IP | ホスト名 | ハードウェア |
|--------|--------|---------|----------|------------|
| 4-6号機 | `10.10.10.24-26` | `10.10.10.204-206` | ayase-web-service-{4,5,6} | Supermicro X11DPU |
| 7-9号機 | `10.10.10.27-29` (iDRAC) | `10.10.10.207-209` | ayase-web-service-{7,8,9} | DELL PowerEdge R320 |
| **10号機 (新規)** | **`10.10.10.30`** | **`10.10.10.210`** | **ayase-web-service-10** | **Supermicro X10DRT-P (Twin Server)** |

10号機の NIC 名 (`eno1np0` / `eno2np1`)、`serial_unit: 1`、`disk: /dev/nvme0n1` は X11DPU 既存値を雛形として記載しており、実機の OS 初回起動時に `ip link` と KVM で検証して必要に応じ修正する。

## 実施内容

### 新規作成

- `config/server10.yml` — `config/server4.yml` を雛形に、bmc_ip/static_ip/hostname/iso_filename を 10号機向けに変更。`bmc_type: supermicro`。NIC・serial_unit・disk には実機検証要のコメントを付与

### 修正

- `CLAUDE.md` — サーバ一覧表に 10号機行追加、注釈に「10号機: Supermicro X10DRT-P (Twin Server) ... LINSTOR 未参加」を追記
- `README.md` —
  - 「対応済みハードウェア」に **`### Supermicro X10DRT-P (10号機)`** サブセクションを追加
  - 「サーバ一覧」表に 10号機行を追加、注釈を更新
  - mermaid 図に `srv10` サブグラフ (`BMC10`, `PVE10`) と接続線 (`SSH`/`IPMI`/`SMB`) を追加。LINSTOR 未参加のため `IB` 線は省略
- `/home/ubuntu/.claude/projects/-home-ubuntu-projects-pvese/memory/MEMORY.md` (auto-memory) — サーバ情報表に 10号機列を追加、注釈を更新
- `ssh/config` — `pve9` の後に `pve10` (HostName `10.10.10.210`) エントリを追加

### 触らなかったもの (明示)

- スキル定義 (`.claude/skills/*`) は全て不変
  - `os-setup`: Platform Dispatch で `bmc_type` 自動判別。`config/server10.yml` 追加のみで対応
  - `linstor-*`: LINSTOR 未参加のため argument-hint 等への追加なし
  - `bios-setup`: X11DPU 専用のまま据え置き (ユーザ確認済み)
  - `perc-raid`, `idrac7`, `idrac7-fw-update`: それぞれ DELL R320 専用、X10DRT-P は対象外
  - `ib-switch`, `dell-fw-download`, `tftp-server`, `playwright`: サーバ非依存
- `config/linstor.yml`: 未参加のため変更なし
- `scripts/*`: 既存スクリプトはサーバ番号のハードコードがなく、`config/server10.yml` 経由でそのまま動作
- `.claude/settings.local.json` / `settings.local.example.json`: 4-6号機分の preseed sha256sum エントリは元々無く、10号機分も追加不要

## 再現方法

1. `config/server4.yml` を雛形に `config/server10.yml` を新規作成 (bmc_ip/static_ip/hostname/iso_filename を変更、実機検証要フィールドにコメント付与)
2. `CLAUDE.md` のサーバ一覧表に 10号機行追加 + 注釈更新
3. `README.md` の対応ハードウェアセクション、サーバ一覧表、mermaid 図に 10号機を追加 (IB 線は引かない)
4. `MEMORY.md` (auto-memory) のサーバ情報表に 10号機列を追加
5. `ssh/config` に `pve10` エントリ (HostName `10.10.10.210`) を追加

### 検証コマンド

```sh
./bin/yq '.bmc_ip' config/server10.yml      # → 10.10.10.30
./bin/yq '.hostname' config/server10.yml    # → ayase-web-service-10
./bin/yq '.bmc_type' config/server10.yml    # → supermicro
./bin/yq '.static_ip' config/server10.yml   # → 10.10.10.210
```

ドキュメント反映確認:

```sh
grep -n 'server10\|10\.10\.10\.30\|10\.10\.10\.210\|ayase-web-service-10\|X10DRT-P\|pve10' \
  CLAUDE.md README.md ssh/config config/server10.yml
```

## 検証結果

- `./bin/yq` による設定値抽出: `bmc_ip=10.10.10.30`, `hostname=ayase-web-service-10`, `bmc_type=supermicro`, `static_ip=10.10.10.210` を確認
- `grep` による反映確認: `CLAUDE.md`, `README.md`, `ssh/config`, `config/server10.yml`, `MEMORY.md` のいずれも 10号機関連の記載が期待箇所に存在
- BMC 疎通 (`ipmitool -I lanplus -H 10.10.10.30 -U claude -P Claude123 chassis status`) は実機側のユーザ初期化状況に依存するため本作業では未実施

## 残タスク (別タスクで実施)

1. **BMC 初期化確認** — `claude` / `Claude123` で `ipmitool` 接続できるか。出荷状態であれば BMC Web UI/CGI で claude ユーザ作成が必要
2. **NIC 名 / serial_unit / disk の実機確認** — OS 初回起動時に `ip link` と KVM で確認し、X11DPU と異なれば `config/server10.yml` を修正

5. **`bios-setup` スキルの X10DRT-P 対応** — BIOS UI を KVM で実機確認し、X11DPU と互換なら SKILL.md の対応サーバ表を拡張、非互換なら専用 reference を作成
