## 実施した恒久対策

### #15 — PXE cmdline で install NIC を eno1 に固定 (主対策)

**真の修正レバーは preseed の `netcfg/choose_interface` ではなく PXE kernel cmdline の `interface=`**。PXE 経路では preseed をネットワーク越しに取得するため、preseed をダウンロードする netcfg はその preseed が読まれる前に走り終わっており、preseed 指定では #15 に間に合わない。

- **embed iPXE script** (`.claude/skills/pxe-deploy/SKILL.md` + playground `tx1320-embed.ipxe`) の kernel cmdline を `interface=auto` → `interface=eno1`。`ipxe.efi` を再ビルド → playground 公開 → OpenWrt `/tmp/tftp/ipxe.efi` を更新。
- **副対策** (`scripts/generate-preseed.sh` 非VLAN ブロック): `dhcp_secondary_iface` 設定時のみ preseed `choose_interface` を `static_iface` (eno1) に。PXE では cmdline が一次対策、これは整合 + virtual-media/NFS フォールバック経路用。
- PXE NIC は embed iPXE の `isset ${net0/gateway} || goto nogw` で gateway-bearing な site LAN ポート (= eno1) に確定するため、eno1 固定が正しい。

### #14 — installed-system の eno2 を `allow-hotplug` → `auto`

- `scripts/generate-preseed.sh` late_network: `echo 'allow-hotplug ${dhcp_secondary_iface}'` → `echo 'auto ${dhcp_secondary_iface}'`。link-up イベント非依存で起動時に DHCP を確実化。
- この分岐は `network_mode=dhcp` かつ `dhcp_secondary_iface` 設定時のみ実行 = **training-tx1320 専用**で他機種に無影響。

### #10 — 真因は `-L` ではなく iRMC env 未 export (レポートの診断を訂正)

実機で切り分けた結果、**10-run レポートの「rc=52 は `-L` が原因」は誤診**だった:

- 同一 env で PATCH に `-L` あり/なし両方とも **http=200・rc=0** (iRMC `/redfish/v1/Systems/0` は 301 しない)。
- rc=52 の真因は **`BMC_CURL_OPTS="--ciphers DEFAULT@SECLEVEL=0"` の未 export**。iRMC S4 は古い DH 鍵のため cipher option なしだと TLS handshake が失敗し empty reply (rc=52)。
- さらに **`-L` は NX-3060-G5 (11/12号機) の末尾 `/` 301 follow に必要**なので削除してはならない (削除すると boot-override が silent に効かなくなるリグレッション)。
- **対応**: `scripts/bmc-power.sh` の `-L` 除去案は revert。SKILL.md の #10 記述を正しい真因 (env 未 export) + 対策 (`irmc-bios-raid-setup.sh` の `load_config()` と同じ 5 変数を export) に修正し、Step 5 に env export ブロックを追加。

### phonehome バグ (検証中に発見・修正)

- `scripts/generate-preseed.sh` の `--pxe` phonehome 行 `wget ... && sh ...` の `&&` が、awk `esc()` の `&` エスケープ不備により gsub 置換で `%%LATE_NETWORK%%%%LATE_NETWORK%%` に化け、phonehome-setup.sh が **fetch されるが実行されない** silent failure になっていた (10-run が phonehome を信頼せず `ip neigh` に依存していたのと整合)。
- **修正**: `&&` → `;` (+ 末尾 `|| true`) で awk の `&` トラップを回避。`&` を late_network に含めないこと、を警告コメントとして追記。

## 再現方法

```sh
# 0. ipxe.efi を interface=eno1 で再ビルド (playground) → OpenWrt 更新 (ユーザ実行)
ssh playground "sed -i 's/interface=auto/interface=eno1/' tx1320-embed.ipxe; make ... EMBED=tx1320-embed.ipxe; sudo cp bin-x86_64-efi/ipxe.efi /var/www/html/ipxe.efi"
# OpenWrt 上: wget http://10.1.6.6/ipxe.efi -O /tmp/tftp/ipxe.efi

# 1. preseed 再生成 + 配置
./scripts/generate-preseed.sh --pxe=http://10.1.6.6 config/training_tx1320.yml tmp/<sid>/training-tx1320.cfg
scp ... → playground /var/www/html/preseed/training-tx1320.cfg

# 2. iRMC env を export してから bmc-power.sh (#10)
export BMC_SCHEME=https BMC_CURL_OPTS="--ciphers DEFAULT@SECLEVEL=0"
export BMC_PATCH_REQUIRES_ETAG=1 BMC_BOOT_OVERRIDE_NO_DISABLED=1 POWER_ON_RESET_TYPE=On

# 3. 1 run = ForceOff→Off待ち→boot-override Pxe→On→(preseed/phonehome 監視 + auto-poweroff 待ち)→boot-override Hdd→On→IP特定→SSH検証
./oplog.sh sh tmp/<sid>/run-cycle.sh <N>
```

> **完遂判定の注意**: install 自身の **auto-poweroff (PowerState=Off) + phonehome GET** を待つこと。固定時間での proactive ForceOff は finish-install の sync を中断し、最後に書かれる authorized_keys 等を失わせて SSH publickey 不通を招く (Run F2 で再現)。

### F2 の所見 (検証ハーネスのバグ)

F2 は install 自体は完遂 (OEM screenshot で `Debian GNU/Linux 13 tx1320 / login:` 到達確認) したが SSH publickey が不通だった。原因は自律スクリプト初版の **固定ポーリング窓 (20分) が今環境の install 時間 (~21分) より短く**、phonehome 直後 (finish-install の sync 前) に proactive ForceOff したため authorized_keys が RAID に flush されなかったこと。**修正 (auto-poweroff を完遂シグナルに変更)** 後の F3/F4 は正常完遂。修正自体 (#15/#14/#10) とは無関係。

### 追加で判明した知見

1. **phonehome 機能は end-to-end で動作 (修正の完全検証)** — `;` 修正により in-target で `phonehome-setup.sh` が実行され、first-boot systemd oneshot (`pvese-phonehome.service`) が仕込まれ、disk boot 後に `curl http://10.1.6.6/phonehome?host=...&ips=...` で報告するところまで成功。nginx access.log に F1 (18:39:46) / F3 (19:42:29) / F4 (20:10:33) の報告 GET を確認。修正前は GET が `%%LATE_NETWORK%%` 化けで script が実行されず報告ゼロだった。
2. **phonehome の eno2 値は link-local (169.254.x) になりうる** — phonehome は `network-online.target` + 10s 後に最初の成功 curl で exit する。eno1 (site LAN) が先に online を満たすため、**eno2 の DHCP 完了前に発火すると eno2 を `169.254.x` (APIPA) として報告**する (F1/F3 で `eno2=169.254.131.95/16`、F4 では逆に eno1 が link-local・eno2 が `10.254.254.19/8`)。**phonehome の eno2 値は最終的な dark-net lease とは限らず、SSH 到達 IP は `ip neigh \| grep <eno2-MAC>` で再確認が必要**。#14 (auto eno2 で lease 取得) 自体は `ip neigh` で +3 分以内に `10.254.254.x` を確認しており成立。
3. **iRMC は PowerState=On のとき `ResetType=On` を拒否する → ForceOff 後は Off をポーリングしてから on** — 初回 deploy で `ForceOff → 固定 sleep 30s → on` が `Fujitsu.1.0.ActionParameterValueNotInList` (まだ On) で失敗。固定 sleep は不十分で、PowerState=Off になるまでポーリングしてから power on すること。
4. **awk `esc()` は `&` を正しくエスケープできない潜在バグが残存** — 今回 phonehome は `&&`→`;` で**回避**しただけで、`generate-preseed.sh` の `esc()` 関数自体は未修正。今後 late_network 等の値に `&` が混入 (例: `&` 入りパスワード) すると同じ `%%...%%` 化けが再発する。根本修正は別 issue。
5. **installed hostname は `tx1320`** (preseed `netcfg/get_hostname=training-tx1320` にもかかわらず短縮形)。SSH/identity 判定で `training-tx1320` を期待すると外れる。stale ARP に同 MAC の旧 lease (.15/.16 等) が残るため、IP 特定後は hostname probe で live 系を選ぶこと。

## 結論

- フォローアップ 3 点 + phonehome バグをすべて恒久対策し、実機で検証完了。
- **#15 は決定論的に解消** (4/4 で netcfg stuck 0%、baseline 30%)。無人運用の信頼性が向上し、ForceOff+retry の暫定回避が不要になった。
- **#14 は auto eno2 で起動時 DHCP が確実化** (3/3 で +3 分以内、15 分遅延の再現なし)。
- **#10 の真因はレポートの誤診を訂正** (= cipher env 未 export)。`-L` 除去はリグレッションリスクのため不採用とし、env export を文書化。
- 副次的に **phonehome silent failure バグ** を発見・修正 (awk gsub の `&` トラップ)。
