## 重要な発見 (next-session must-read)

### 🎯 1. **iRMC OEM HDImage は license 上利用不可** (Priority #1 経路の dead-end 確定)

OEM probe 出力 `tmp/streamed-parrot/probe-oem-virtualmedia.body` (前セッション残置) を read して判明:

```json
"CDImage": { ..., "MaximumNumberOfDevices": 2 }
"HDImage": { ..., "MaximumNumberOfDevices": 0 }
"FDImage": { ..., "MaximumNumberOfDevices": 0 }
```

実機 PATCH 試行で確証:
- HTTP 200 + 応答 JSON に Server="10.1.6.1" 等反映される (見かけ上 accept)
- ただし `MaximumNumberOfDevices: 0` のまま
- Manager-level VirtualMedia Members 数 = 0 (USB device 生成なし)
- license = KVM + MEDIA でも CDImage 2 スロットのみ、 HDImage/FDImage は実装外

→ 前セッション推奨 Priority #1 (HDImage 経由配信) は技術的に不可能。 **次セッションは Priority #2 (PXE/netboot) 以降を検討**

### 🎯 2. **iRMC SMB silent failure は HDImage PATCH 試行後に発生・固着** (重大、 次セッション最優先 unblock)

タイムライン:
- **07:55**: CDImage status OK (前セッション #8 終了時の state)、 Members=2 想定
- **08:00**: HDImage の PATCH 試行 (Phase 1 検証用)、 HTTP 200 で accept されたが Members=0 のまま
- **08:01**: HDImage の umount (空フィールドで PATCH)、 HTTP 200
- **08:11**: CDImage に patched ISO を再 attach + 電源 On (Phase 2D 1回目 deploy)、 kernel 0.076s 到達
- **08:32 以降**: 同 patched ISO で再 deploy + baseline (HEAD revert) deploy、 すべて kernel boot しないまま GRUB → "Booting `Automated Install`" 表示で hang
- **09:05**: Manager VirtualMedia Members を確認 → **0** (USB attach されず)
- **09:06**: VirtualMediaAction の AllowableValues = `["DisconnectCD"]` (iRMC は "connected" と認識中、 矛盾)
- **09:09**: 強制 disconnect → 待機 → CDImage 再 PATCH → ConnectCD action → **`ActionParameterValueNotInList`** で reject (= 既に attach 試行中状態を抜けられない)
- **09:10**: 30秒 polling しても Members count = 0 のまま

iRMC は内部で「CDImage attached」と思い込んでいるが USB redirector が動作せず、 ConnectCD action も発行できない (= AllowableValues に出ない) 状態。 TCP connection は `10.1.6.1:445 ← 10.254.254.9:37435` ESTABLISHED で生きている。 Samba 側 log には iRMC 接続痕跡なし (= SMB negotiation 段階で hang か、 iRMC が SMB ハンドシェイクを完了させていない)。

**仮説**: HDImage PATCH 試行が iRMC FW の USB redirector 内部 state を破壊。 license 上 0 device な HD slot に SMB 設定を入れたことで、 redirector が「CD と HD を両方管理しようとしたが HD slot が無くて立ち往生」状態に陥った可能性。

**次セッション unblock 候補** (優先順):
1. **iRMC コールドリセット (PSU ケーブル抜差し)** — 唯一確実、 ユーザ依頼必須 (CLAUDE.md 準拠)
2. Samba server restart — ユーザに `sudo systemctl restart smbd` を依頼、 iRMC が stale connection を切り直す可能性 (低確率)
3. 別 SMB share 名 / 別 ISO ファイル名で PATCH — iRMC の cache を bypass (中確率)

### 🎯 3. **cdrom-detect.postinst patch (pvese-patch v1) を `scripts/remaster-debian-iso.sh` に env-gate 付きで実装** (動作未検証)

#### Patch 設計

cdrom-detect.postinst の L111 `while true; do` 直前に `/dev/sr1` を最優先試行する 9 行 block を挿入し、 L112 直後に短絡 break 1 行を挿入。 list-devices 経路を bypass。

```sh
# pvese-patch v1 - TX1320 /dev/sr1 priority (iRMC virtual CD; /dev/sr0 is the empty physical DVD)
# Safe no-op when /dev/sr1 does not exist or does not contain a Debian CD.
if [ "$OS" = "linux" ] && [ -b /dev/sr1 ]; then
    if try_mount /dev/sr1 $CDFS; then
        set_suite_and_codename
        log "pvese-patch: bypassed list-devices via /dev/sr1 direct mount"
        pvese_skip_main_loop=1
    fi
fi
while true; do
    [ "${pvese_skip_main_loop:-0}" = 1 ] && break  # pvese-patch v1
    ...  (元 logic そのまま、 fall through)
done
```

実装方式:
- 元 cdrom-detect.postinst を docker container 内で `cpio -idm var/lib/dpkg/info/cdrom-detect.postinst` で partial extract
- awk script (heredoc 経由ファイル) で 1 箇所 sed 風 in-place 注入
- `sh -n` syntax check + grep marker check
- 注入用 cpio archive を `find . -mindepth 1 -print | cpio -o -H newc` で作成 (directory entry 込み)
- 元 initrd.gz と新 extra.cpio.gz を `cat` で連結 (concatenated archive)

env 変数 `PVESE_PATCH_CDROM_DETECT=1` で有効化、 デフォルト 0 (= 注入しない baseline)。

#### Sanity check 4 項目すべて pass (build 段階)

```

Stream 2 preseed.cfg entries: 1 (expected: 1)
Stream 2 cdrom-detect.postinst entries: 1 (expected: 1)
pvese-patch v1 marker count: 2 (expected: >=1)
/dev/sr1 reference count: 8 (expected: >=1)
```

→ ISO 生成は正常、 patched postinst は 297 行 7185 bytes で initrd 内に正しく配置。

2回目以降の deploy では iRMC SMB silent failure で host が GRUB → kernel handoff 後すぐ hang (Members=0 で USB CD が消えた状態)。 patch validation 完全 blocked。

## 重要な教訓 (次セッションへの引き継ぎ)

1. **HDImage は license 上 0 device** (`MaximumNumberOfDevices: 0`)。 PATCH は HTTP 200 で見かけ accept されるが実機への USB attach は起こらない。 Priority #1 経路は閉鎖
2. **HDImage PATCH 試行は iRMC USB redirector を破壊する** (副作用) — 試行後 iRMC が「CDImage attached」と思い込んだまま実際は Members=0 の silent failure 固着状態に陥る。 復旧には恐らく iRMC コールドリセット必須。 **次セッション以降、 license 不可な OEM スロット (HD/FD) への PATCH 試行は厳禁**
3. **patched cdrom-detect.postinst を initrd 注入する方式は build 段階で sanity check pass** だが実機動作は未検証。 次セッションで iRMC 復旧後に `PVESE_PATCH_CDROM_DETECT=1` で検証必要
4. **kernel hang at 0.076s "SGX disabled"** が 1 回目 deploy で観測されたが、 直後の iRMC 不調により再現性確認不可。 patch のせいか偶発か未確定
5. **`scripts/irmc-virtualmedia.sh --type=` flag** は引き続き使用可能 (HD/FD は実機で動かないが API 試験には有用、 状態確認に使う場合 license-blocked は前提)
6. **`PVESE_PATCH_CDROM_DETECT` env-gate** は default 0 (= baseline)、 次セッションで `=1` set して deploy 試行 → 動作確認後、 default を 1 に変更検討
7. **SMB silent failure 切り分け checklist**: (a) `./scripts/irmc-virtualmedia.sh --type=CD status` で Server/Share/Image 確認、 (b) Manager VirtualMedia Members count、 (c) System Action AllowableValues `Connect`/`Disconnect` 切り替わり、 (d) Samba log と TCP ESTABLISHED 状態、 (e) Samba 再起動で stale connection 切る
