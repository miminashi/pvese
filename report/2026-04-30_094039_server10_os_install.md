## 前提・目的

10号機 (Supermicro X10DRT-P, Nutanix NX-1065-G5 OEM) に Debian 13 + Proxmox VE を初期インストールする。10号機は **別拠点設置** で、host LAN は 1 本の VLAN trunk (1120/1083) で配信されており、4-9号機の物理 NIC 直結構成と前提が異なる。本作業ではホスト NIC・VLAN 構成を実測した上で、`os-setup` スキル系の preseed/scripts を VLAN 対応に拡張し、自動インストール経路を整備する。

- 背景: 10号機は 2026-04-30 に追加された Twin Server (X10DRT-P-G5-NI22 / NX-1065-G5)。BMC は到達済みだが、host NIC や VLAN 構成は未確認だった
- 目的: (1) 物理ポートと VLAN 配信を実測、(2) 既存スクリプトを VLAN 対応に拡張、(3) Debian + PVE をインストール
- ユーザ確認済みの方針:
  - 1 本の VLAN trunk (1120 = DHCP/インターネット, 1083 = 10.0.0.0/8 mgmt 共通)
  - BMC は IPMI 専用ポート (host NIC と独立)
  - ケーブル調査は Debian インストーラ rescue shell から実測
  - 既存スクリプトを VLAN 対応に拡張 (10号機専用派生は作らない)
  - 別拠点のため VLAN 1120 のサブネット/GW は 4-9号機の `192.168.39.0/24` とは別 (DHCP で動的取得)

## 実施内容

### Phase 0: 物理ポート/VLAN 構成の実測

- Debian 13.3 stock ISO を BMC VirtualMedia でマウント、Power cycle
- ISOLINUX → "Install" (text mode) → Country/Locale/Keymap 連続 Enter で進行 → Network detection で NIC 列挙を観察
- `Detecting link on eno1` のみが d-i に表示され、untagged DHCP 失敗 → 静的 IP 入力 prompt
  - link up な物理 host NIC は **`eno1` のみ**
  - untagged DHCP 失敗 = trunk である強い証拠
- 副次発見: BIOS mode 表示 = X10DRT-P は Legacy BIOS で起動 (UEFI ではない)
- BMC FW 3.65 stock の Redfish 経路差異を確認:
  - 4-9号機 (新 FW): `/redfish/v1/Managers/1/VirtualMedia/CD1`
  - 10号機: **`/redfish/v1/Managers/1/VM1/CD1`**、フィールド名 **`ConnecteVia`** (typo)

### Phase A: VLAN 対応スクリプト/preseed 拡張

VLAN フィールドを config に追加すれば自動で VLAN 動作、無ければ従来動作 (4-9号機後方互換) という設計で全体を実装。

#### preseed VLAN モードの設計判断

当初 preseed の `early_command` で `modprobe 8021q + ip link add type vlan` を試みたが、stock netinst initrd には `net/8021q/` kernel module が含まれていないため modprobe 失敗 → netcfg セグフォルト → install 中断 (iter1a で観測)。

そこで方針を切替え、**VLAN モード = CD-only install + post-install で VLAN bridge** とした。具体的には:
- `netcfg/disable_autoconfig boolean true` で d-i の DHCP スキップ + 静的 IP の fallback 値を preseed で feed
- `apt-setup/use_mirror false` で apt mirror アクセスを完全に避ける
- `tasksel/first` 空 + `pkgsel/include openssh-server` のみ (CD に無い curl/wget/gnupg を要求しない)
- `late_command` で `/target/etc/modules` に 8021q を追記 + `eno1.1083` (静的) と `eno1.1120` (DHCP) を `/target/etc/network/interfaces` に書込み

これにより first boot で kernel が 8021q を auto-load し、ifupdown が VLAN サブを起動して 10.10.10.210 と DHCP 取得側 IP の両方を持つ状態になる。pre-pve-setup.sh は `--dhcp-iface eno1.1120` で動作 (GW は L83-85 で動的検出済み)。

### Phase B: OS インストール (iter1)

- Phase 1-3: ISO ダウンロード済み、preseed-generated-s10.cfg 生成、ISO リマスター完了 (debian-preseed-s10.iso, 763MB)
- Phase 4: BMC VirtualMedia (修正版 verify) でマウント成功 (`Inserted: true via Managers/1/VM1/CD1`)
- Phase 5: ISOLINUX → preseed automated install
- iter1 試行回数 (preseed 修正の繰返しを反復として記録):
  - iter1a: VLAN early_command で 8021q load 失敗 → netcfg segfault
  - iter1b: CD-only モード化、static IP directive 未指定で IP 入力 prompt で停止 → 手動入力で先に進めるが pkgsel `standard` task が CD に無く失敗
  - iter1c: pkgsel skip + disk path `/dev/sda` 修正前で partman "No root file system"
  - iter1d: disk path 修正後、`tasksel/first` 空 + `pkgsel/include openssh-server` のみで `Sent SIGKILL → Requesting system poweroff → reboot: Power down` まで完走 → **PowerState=Off**
  - iter1e: 上記 preseed のまま再実行 → 同様に install 完走 → PowerState=Off。 **同一 preseed で install 自動再現** を確認 (= preseed の自動性検証成功)
- Phase 6 開始: VirtualMedia アンマウント + Power on
  - **disk からブート失敗** (`Reboot and Select proper Boot device or Insert Boot Media`)
  - PXE フォールバック → DHCP 失敗 (untagged) → boot device 不在で停止
  - SSH 240 秒・180 秒の 2 回試行、両回ともタイムアウト → 残作業として未完了
  - BMC KVM 経由の DEL/F2/F11/F12 連打はいずれも BIOS Setup or Boot Override メニューに到達できず (USB HID emulation 制約と推測)

> **install は完走した** (`reboot: Power down` 観測 = preseed exit/poweroff true) が、disk からの **first boot がブート不能**。Legacy BIOS の boot order に SATA disk が含まれていない or grub-pc の MBR インストールが silently 失敗した可能性が高い。BMC KVM 経由の BIOS Setup 入場 (DEL/F11/F2 連発) はいずれも効果なく、原因の特定には rescue mode での実機確認が必要。

## 再現方法

### Phase 0 (調査)

```sh
# Stock ISO を BMC VirtualMedia でマウント
./scripts/bmc-session.sh login 10.10.10.30 claude Claude123 tmp/<sid>/bmc-cookie
CSRF=$(./scripts/bmc-session.sh csrf 10.10.10.30 tmp/<sid>/bmc-cookie)
./scripts/bmc-virtualmedia.sh config 10.10.10.30 tmp/<sid>/bmc-cookie "$CSRF" 10.1.6.1 '\public\debian-13.3.0-amd64-netinst.iso'
./scripts/bmc-virtualmedia.sh mount 10.10.10.30 tmp/<sid>/bmc-cookie "$CSRF"
./scripts/bmc-virtualmedia.sh verify 10.10.10.30 claude Claude123  # 修正版で /VM1/CD1 にフォールバック

# Power cycle、ISOLINUX で "Install" 起動 (text mode default)
./pve-lock.sh wait ./scripts/bmc-power.sh cycle 10.10.10.30 claude Claude123 20

# Country/Locale/Keymap を Enter 連続送信、Network detection で NIC 名と link 状態を観察
python3 ./scripts/bmc-kvm-interact.py --bmc-ip 10.10.10.30 --bmc-user claude --bmc-pass Claude123 \
    sendkeys Enter Enter Enter Enter Enter --wait 5000 --post-wait 5000 \
    --screenshot tmp/<sid>/network-detection.png
```

### Phase A (拡張実装)

```sh
# config を VLAN フィールド付きで設定
$EDITOR config/server10.yml  # vlan_iface, internet_vlan_id, internal_vlan_id, static_gateway, disk: /dev/sda

# preseed 生成 (VLAN モード自動判定)
./scripts/generate-preseed.sh config/server10.yml preseed/preseed-generated-s10.cfg
grep -E 'disable_autoconfig|use_mirror|tasksel|pkgsel/include|disk string|8021q|vlan-raw' preseed/preseed-generated-s10.cfg
```

### Phase B (OS インストール)

```sh
./scripts/os-setup-phase.sh init --config config/server10.yml

# iso-download / preseed-generate / iso-remaster
./scripts/os-setup-phase.sh start iso-download --config config/server10.yml
./scripts/os-setup-phase.sh mark iso-download --config config/server10.yml
./scripts/os-setup-phase.sh start preseed-generate --config config/server10.yml
./scripts/generate-preseed.sh config/server10.yml preseed/preseed-generated-s10.cfg
./scripts/os-setup-phase.sh mark preseed-generate --config config/server10.yml
./scripts/os-setup-phase.sh start iso-remaster --config config/server10.yml
./scripts/remaster-debian-iso.sh /var/samba/public/debian-13.3.0-amd64-netinst.iso \
    preseed/preseed-generated-s10.cfg /var/samba/public/debian-preseed-s10.iso
sha256sum preseed/preseed-generated-s10.cfg | awk '{print $1}' \
    > /var/samba/public/debian-preseed-s10.iso.preseed-sha256
./scripts/os-setup-phase.sh mark iso-remaster --config config/server10.yml

# bmc-mount-boot (VirtualMedia mount + Power cycle)
./scripts/os-setup-phase.sh start bmc-mount-boot --config config/server10.yml
./scripts/bmc-session.sh login 10.10.10.30 claude Claude123 tmp/<sid>/bmc-cookie
CSRF=$(./scripts/bmc-session.sh csrf 10.10.10.30 tmp/<sid>/bmc-cookie)
./scripts/bmc-virtualmedia.sh config 10.10.10.30 tmp/<sid>/bmc-cookie "$CSRF" 10.1.6.1 '\public\debian-preseed-s10.iso'
./scripts/bmc-virtualmedia.sh mount 10.10.10.30 tmp/<sid>/bmc-cookie "$CSRF"
./pve-lock.sh wait ./scripts/bmc-power.sh cycle 10.10.10.30 claude Claude123 20
./scripts/os-setup-phase.sh mark bmc-mount-boot --config config/server10.yml

# install-monitor (SOL 経由、preseed automated install を 12 分待機)
./scripts/os-setup-phase.sh start install-monitor --config config/server10.yml
./scripts/sol-monitor.py --bmc-ip 10.10.10.30 --bmc-user claude --bmc-pass Claude123 \
    --log-file tmp/<sid>/sol-install-s10.log --max-reconnects 3 --timeout 1500
# PowerState=Off + stage 観測 → install 完走
./scripts/os-setup-phase.sh mark install-monitor --config config/server10.yml
```

### 検証コマンド (現状で動く部分)

```sh

```

## 残タスク

| 優先度 | 内容 |
|-------|------|
| **最高** | **disk からの first boot 不能の調査と対処** — Stock ISO の rescue mode で `/dev/sda` を mount → `/var/log/installer/syslog` で grub-install の exit status を確認 → 必要なら chroot で `grub-install /dev/sda` 再実行。 BIOS Boot Order に disk が含まれていない可能性も調査 (BMC SOL に BIOS console redirection がある場合 SOL 経由で BIOS Setup 入場可能)。 BMC KVM 経由の DEL/F2/F11 はいずれも届かなかった (USB HID emulation 制約) |
| 高 | スキル安定化 (iter2-3 反復) — disk boot 問題が解決した後、 state リセット → Phase 4-8 再走を 2 反復実行して preseed の自動再現性を確認 |
| 高 | Phase 7-8 (PVE インストール + bridge セットアップ) の実証 — 上記 disk boot 問題が解決した後 |
| 中 | `bmc-kvm-interact.py` に combo key (Ctrl+Alt+F2 等) サポート追加 — Phase 0 で TTY 切替が困難だった (initrd framebuffer + browser キャプチャ制約) |
| 中 | 4-9号機の preseed regenerate 検証 — preseed.cfg.template に新規 directive (`netcfg/disable_autoconfig`, `apt-setup/cdrom/set-*` 等) を追加したため、 4-9号機の install 時に挙動差が出ないか実機確認 (現状は preseed 生成のみで動作確認済み、実 install は未) |
| 低 | BIOS mode UEFI 切替検討 — 現状 Legacy BIOS で動作、 NVMe 移行や UEFI Secure Boot 要求が出た場合は bios-setup スキルを通じて変更 |
