## 未完了 / 次セッション課題 (Phase 3)

### 1. 🎯 最優先: GRUB→kernel ハンドオフ後の console 沈黙の真因究明

仮説候補 (優先順、 5 は本セッションで反証済):

1. **`nomodeset` の組み合わせで kernel が early panic** (VGA/SOL 初期化前) — 試行: GRUB cfg から `nomodeset` `vga=normal` を抜く / `earlyprintk=ttyS0,115200n8` を追加
2. **BIOS Serial Console Redirection が OS hand-off で OFF になる** — BIOS Setup で "Console Redirection" / "Redirection After BIOS POST" の有無を XML backup で確認、 必要なら apply-config で Enabled 化
3. **iRMC NFS USB CD-ROM は GRUB 用 short read には応答するが kernel の長尺 access (initrd 全 load 後の cdrom-detect 等) で stall** — Phase 1 検証 (NFSv4 54 ops) は短時間のみ、 longer fetch で hang の可能性。 10.1.6.6 で `sudo tcpdump -i ens19 -nn 'host 10.254.254.9 and port 2049'` を boot 中に capture して NFS access pattern + 異常終了点を観測
4. **kernel `--- quiet` の影響** — `quiet` を `verbose` または無印に変更し早期 message を強制可視化
5. ~~**Legacy BIOS 経路に切替**~~ — **本セッションで実機反証済**。 UEFI/Legacy 両モードで同症状なので真因は UEFI EFI stub 固有でない

### 2. SOL 経路の独立検証

- BIOS apply-config で `BiosConsoleRedirectPort=COM1` / `BiosConsoleRedirectAfterPost=AlwaysEnable` を明示
- ipmitool sol info 2 で SOL channel 設定確認 (`-c` で channel info)、 SOL volatile/non-volatile 比較
- BIOS Setup に直接入って Console Redirection の現状を screenshot で確認 (`bios enter` skill)

### 3. cdrom-detect patch の挙動検証 (kernel が動いた後の話)

Phase 2 で patched ISO は build 済 + sha256 整合確認済だが、 kernel が boot しないため実機検証未到達。 Phase 3 で kernel hang が解消したら自動的に検証される。

### 4. memory / SKILL.md 追記

- memory に「GRUB→kernel jump 後の沈黙」追記 (training_tx1320_kernel_boot_silent.md 新規予定)
- SKILL.md の「落とし穴」に `nomodeset` + UEFI + NFS CDImage の組み合わせ警告を仮置きし、 真因確定で更新

### 5. NFS server (10.1.6.6) export の bind 範囲拡張検討

現状 `10.0.0.0/8` のみ。 別 server (例 10.10.10.0/8 = 4-9号機 LAN) からも NFS export を使うなら range 拡張。 本セッション無関係。

5. **🎯 PVESE_PATCH_CDROM_DETECT=1 は orchestrate build に env で渡す**: `PVESE_PATCH_CDROM_DETECT=1 ./oplog.sh ./scripts/tx1320-raid10-orchestrate.sh build ...`。 未指定だと baseline (no patch) で build される。 sanity check は build script 末尾で自動 verify (TRAILER 2 + preseed.cfg 1 + cdrom-detect.postinst 1 + marker 2 + /dev/sr1 8)
6. **NFS rsync は ubuntu 所有 /tmp/ 経由 + sudo mv**: `/var/samba/public/` は root 所有なので直接 rsync 不可。 一旦 `/tmp/` に push して `sudo mv` する流れが必要
7. **iRMC ResetType は `ForceOff` を AllowableValues 動的に On 時のみ受理**: Off 状態で `ForceOff` 発行は `Fujitsu.1.0.ActionParameterValueNotInList`。 orchestrate scripts は `|| true` でこれを吸収済
8. **NFS export reload は `sudo exportfs -ra`**: ISO 差し替え時に必要 (NFSv4 cache が古い handle を返す場合あり)。 本セッションは exportfs -ra + 新 ISO 配置で symptom 変化なし、 真因は kernel hang 側
