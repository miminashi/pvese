## 実施内容と結果

### Phase 1: 実機探索 (完了)

#### 1-1. Redfish/curl で現状確認
- PowerState=On, BootSourceOverrideTarget=None
- BIOS Information (Manufacturer, Model, BiosVersion, SerialNumber, Memory) ほぼ前セッションと一致
- OEM `BootConfig` (`/redfish/v1/Systems/0/Oem/ts_fujitsu/BootConfig`): BootType=Legacy (キャッシュ値、 BSPBR XML 経由で恒久 boot mode が決まる)

#### 1-2. WinSCU XML ダウンロード経路の確立 (**新発見**)

OEM `FTSBios.BSPBRBackup` / `FTSBios.BSPBRRestore` / `FTSBios.BSPBRSaveBackupToFile` の挙動を実機検証:

- **Backup は BIOS Boot Phase で実行される**: POST `FTSBios.BSPBRBackup` → Task /N (`StatusOEM: BSPBRBootPhasePending`) → サーバを cycle で再起動 → boot phase で `BSPBRBootInProgress` → Completed `BSPBRSuccess`
- **`IsBspbrFileAvailable: true` の確認後、`FTSBios.BSPBRSaveBackupToFile` の POST (`Content-Type: application/json`, body `{}`) で WinSCU XML を `application/octet-stream` でダウンロード**
- **XML 末尾に NUL bytes (`\x00\x00`)**: Python `xml.etree.ElementTree.fromstring()` が "not well-formed" で失敗。`text.rstrip(b"\x00\r\n\t ")` で除去してから parse
- **XML スキーマは 2 セクション構成**:
  - `<settingDefinitions>` (read-only、 各 setting の id/name/possibleValues 定義、 91 entries)
  - `<configuration>` 内 `<supportedSetting>` (restore 対象、 `<value>` を書き換えて適用)

#### 1-3. BSPBRRestore の payload 形式 (**新発見**)

試行錯誤で確定:

- `Content-Type: application/octet-stream` → HTTP 406 (`Fujitsu.1.0.ContentTypeNotSupported`)
- `Content-Type: application/xml` / `text/xml` / `application/x-www-form-urlencoded` → 全て同じ 406
- `Content-Type: multipart/form-data` (field 名 `file`) → 400 (`Fujitsu.1.0.DeclaredDataNotPresent`)
- **`-F "data=@bios.xml"` (multipart, field 名 `data`)** → HTTP 202 + Task URL を返す ✓

#### 1-4. BIOS Setup 進入と OEM Screenshot Make の挙動 (**問題判明**)

- `boot-override BiosSetup UEFI` + cycle で BIOS Setup 進入は可能 (Aptio Main 画面 OEM Screenshot 取得成功 — 添付画像参照)
- しかし **BIOS Setup の Aptio HII 内では OEM Screenshot Make が安定して動かない**: `FTSScreenshotType` AllowableValues に `Preview` が遷移しない (`["Make"]` のまま停滞、 30 秒 polling しても変化なし)
- **HTML5 KVM canvas も同様**: viewer 起動直後は alive=True でも canvas は真っ黒、 Control 単独キー送信でも frame full が来ない (BIOS Setup HII 中の挙動)
- iRMC Web UI の `<div id="processing_maindiv">` overlay が canvas をブロックする問題があり、 `focus_kvm()` で hide してから click する対応を実施 ([scripts/irmc-kvm-interact.py](../scripts/irmc-kvm-interact.py))

#### 1-5. RAID controller 確定

- ユーザ確認で **PRAID EP400i** (LSI MegaRAID SAS3008、 Slot 4)
- BIOS Setup → Advanced → AVAGO MegaRAID Configuration Utility (UEFI HII) が想定経路

### Phase 2: BIOS 設定完全自動化 (Layer 1, XML 経由) — **完了** ✓

新規スクリプト + ラッパー実装:

- [scripts/irmc-bios.py](../scripts/irmc-bios.py) — WinSCU XML backup/restore/show/set/diff/apply-config
  - `backup <out.xml>` — BSPBRBackup → SaveBackupToFile (curl 経由)
  - `restore <in.xml>` — `-F "data=@xml"` で multipart POST
  - `show <xml> [regex]` / `set <xml> <id> <value>` / `diff <a> <b>` / `apply-config <config.yml>`
- [scripts/irmc-bios-raid-setup.sh](../scripts/irmc-bios-raid-setup.sh) — 統合ラッパー
  - `discover <config>` — 現状取得 (power, BIOS, BootConfig, BIOS settings)
  - `setup-bios <config> [--cycle]` — config['bios_settings.supported'] を XML に書き込み → restore (`--cycle` で boot phase 起動)
  - `verify-bios <config>` — 現状の BIOS settings が config と一致するか確認
  - `setup-raid10 <config>` — (TBD) BIOS UEFI HII 経由の RAID10 作成 (本セッションでは TBD)
  - `full-setup <config>` — setup-bios → cycle → verify-bios → setup-raid10

config 拡張:

```yaml
# config/training_tx1320.yml
raid_controller: "PRAID EP400i"
bios_settings:
  supported:
    BootOptionFilter: "UEFI only"
    LaunchStorageOpRomPolicy: "UEFI only"
    LaunchPxeOpRomPolicy: "UEFI only"
    LaunchVideoOpRomPolicy: "UEFI only"
    SerialPort1: "Enabled"
    Csm: "Disabled"
```

**実機検証結果** (再現可能):

```sh
# 1. 初期 backup 取得 (boot phase 経由)
.venv/bin/python scripts/irmc-bios.py --bmc-ip 10.254.254.9 --bmc-user claude --bmc-pass Claude123 \
    backup tmp/biosraid/bios-backup-initial.xml
# → Task /2 Pending → cycle → BSPBRSuccess → IsBspbrFileAvailable=true → ダウンロード (72621 bytes)

# 2. BootOptionFilter 等を UEFI only に書換
.venv/bin/python scripts/irmc-bios.py set tmp/biosraid/bios-uefi.xml BootOptionFilter 'UEFI only'
# (同様に LaunchStorageOpRomPolicy, LaunchPxeOpRomPolicy, LaunchVideoOpRomPolicy も書換)

# 3. Restore POST
.venv/bin/python scripts/irmc-bios.py --bmc-ip 10.254.254.9 --bmc-user claude --bmc-pass Claude123 \
    --skip-wait restore tmp/biosraid/bios-uefi.xml
# → Task /5 (BSPBRRestore : bios-uefi.xml) Pending

# 4. cycle で boot phase 起動 → 適用
BMC_SCHEME=https BMC_CURL_OPTS='--ciphers DEFAULT@SECLEVEL=0' \
    ./oplog.sh ./scripts/bmc-power.sh cycle 10.254.254.9 claude Claude123 25
# → Task /5 BSPBRBootInProgress → BSPBRWriting → Completed BSPBRSuccess

# 5. 反映確認
curl ... FTSBios.BSPBRSaveBackupToFile → tmp/biosraid/bios-current.xml
.venv/bin/python scripts/irmc-bios.py show tmp/biosraid/bios-current.xml 'BootOptionFilter|LaunchStorageOpRomPolicy|...'
# → BootOptionFilter = UEFI only ✓
# → LaunchStorageOpRomPolicy = UEFI only ✓
# → LaunchPxeOpRomPolicy = UEFI only ✓
# → LaunchVideoOpRomPolicy = UEFI only ✓
```

### Phase 3: RAID10 構成自動化 (Layer 2, BIOS UEFI HII 経由) — **未完成** ⚠️

VGA frame buffer 問題で BIOS UEFI HII 上の自動操作ができず、 RAID10 の自動作成は本セッションでは未完成。

**観察**:
- BIOS Setup 進入直後の最初の 1 回は OEM Screenshot Make + Preview に成功 (Aptio Main 画面の鮮明な JPEG 1024x768 を取得)
- しかし、 2 度目以降の Make は AllowableValues に `Preview` が遷移しない (`["Make"]` で固定)
- HTML5 KVM viewer も同様: alive=True で接続は成立しているが canvas に frame が来ない
- Playwright で送ったキー (ArrowDown/F2/Enter 等) は受理されるが画面更新が KVM に届かない

**推定原因**:
- BMC の VGA frame buffer pipeline が UEFI mode + Aptio HII の組み合わせで動作不安定
- KVM WebSocket は server 側で active session lock を取っているが frame buffer がほぼ空
- BIOS Setup から実は抜けてしまっている可能性 (boot-override Continuous も Once と同じ挙動)

**次セッションで試す候補**:
1. BMC Manager Reset (`./scripts/bmc-power.sh` に未実装、 OEM `iRMCConfiguration.Reset` を直接 POST) → VGA pipeline 再初期化
2. OS Live ISO (Debian Live 等) を Virtual Media マウント → ホスト起動 → SSH 接続 → broadcom 公式 `storcli` をインストール → `storcli /c0 add vd r10 drives=...` で RAID10 作成
3. BIOS Setup の "BIOS Frame Buffer Mode" 設定 (HII でしか変更不可で chicken-and-egg) を OEM `BootConfig` PATCH 等の別経路で変更
4. Aptio HII にローカル PC のブラウザ (Chrome/Firefox) から直接 KVM viewer を開いてユーザ手動操作 (完全自動化ではないが現実的な fallback)

## 再現方法

### BIOS UEFI 化 (Phase 2 完成形)

```sh
# 1. 初期状態確認
./scripts/irmc-bios-raid-setup.sh discover config/training_tx1320.yml

# 2. UEFI 化 (BSPBR XML 経由、 cycle で boot phase 起動)
./scripts/irmc-bios-raid-setup.sh setup-bios config/training_tx1320.yml --cycle

# 3. boot phase 完了 (~2-3 分) を待ってから verify
./scripts/irmc-bios-raid-setup.sh verify-bios config/training_tx1320.yml
```

### BSPBR Backup/Restore の単発

```sh
# Backup (boot phase 経由でファイル生成)
.venv/bin/python scripts/irmc-bios.py \
    --bmc-ip 10.254.254.9 --bmc-user claude --bmc-pass Claude123 \
    backup tmp/biosraid/bios.xml
# (cycle が必要、 もしくは --skip-wait で POST のみ → 別経路で cycle)

# Edit
.venv/bin/python scripts/irmc-bios.py set tmp/biosraid/bios.xml BootOptionFilter 'UEFI only'

# Show / Diff
.venv/bin/python scripts/irmc-bios.py show tmp/biosraid/bios.xml 'Boot|UEFI'
.venv/bin/python scripts/irmc-bios.py diff tmp/biosraid/bios-before.xml tmp/biosraid/bios-after.xml

# Restore
.venv/bin/python scripts/irmc-bios.py \
    --bmc-ip 10.254.254.9 --bmc-user claude --bmc-pass Claude123 \
    --skip-wait restore tmp/biosraid/bios.xml
# → cycle 必要
```
