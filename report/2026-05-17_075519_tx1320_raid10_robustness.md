## 前提・目的

前セッションで RAID 10 commit が未完遂 (個別 drive toggle が silent drop 30-50%、 「more than one span」エラー、 NVRAM pending state 持続)。 ユーザ指示「試行→skill やスクリプトの修正を 10 回繰り返し」に従い、 同一ゴール (RAID 10 VD0 commit) を 10 iter で改善する計画。

## 実施内容

### iter 1: fingerprint DB 構築 ✅ PASS

`tmp/iter/_util.py` + `tmp/iter/fingerprints.json` を作成。 既存 v6-v14 PNG から **23 個の fingerprint** (size + state name + desc) を抽出。 `identify_state(size, tol)` で逆引き、 `assert_state()` で照合。 partial-access dialog dismiss helper も追加 (HTML overlay の Ok ボタンを JS click)。

### iter 2: v16 リプレイ + 脱線箇所特定 ✅ PASS (baseline 計測)

`safe_navigate_to_advanced_tab(vp, sdir)` を実装し v16 を再走。 発覚した実機問題:
- **Exit-Without-Saving dialog** が頻出 (Esc 連打で出る)。 `n` キーは Aptio で無効、 **ArrowRight (No) + Enter** で dismiss が正解
- **size fingerprint tol=200 は粗すぎ**、 隣接 menu items が衝突 (例: advanced_avago_row 18091 vs pci_subsystem 18058)。 → tol=80 に下げる + size-only では adjacent items 識別不可能と判明
- BMC が KVM session 多用で過負荷化、 login timeout 頻発

### iter 3: nav_arrowdown_to() → nav_cursor_to_y() 実装 ✅ PASS

**重大ブレイクスルー**: size-only fingerprint では隣接 menu items 区別不可と判明。 **PIL でカーソル ► (white pixel value=255 の連続 run) の Y 座標を pixel-level 検出**する `detect_cursor_row(png_path, x_min, x_max, y_min, y_max, cursor_pixel_value, min_cursor_run)` を実装。 cursor_y は ArrowDown ごとに完全に単調増加 (line_height=19px)。

`nav_cursor_to_y(vp, sdir, target_y, max_press, tol, label, key, ..., allow_overshoot_correct)`:
- target_y に着地するまで指定キー (default ArrowDown) を adaptive 押し
- overshoot 時は反対方向キーに自動切替
- silent drops を完全に吸収

**iter 3b 実証**: 初期 cursor_y=412 (Intel I210 #1) から target_y=393 (AVAGO MegaRAID) へ:
- press 1: ArrowDown → y=431 (overshot, switch to ArrowUp)
- press 2: ArrowUp → y=412
- press 3: ArrowUp → y=393 ✅ **PASS** (3 presses)

### iter 4: AVAGO HII cursor_y mapping ✅ PASS

AVAGO Main → Main Menu submenu → Configuration Management submenu の cursor_y を scan。 確定値:

```python
CURSOR_Y_AVAGO_MAIN_MENU = {  # Main Menu submenu items
    "configuration_mgmt": 70,
    "controller_mgmt": 83,
    "virtual_drive_mgmt": 102,
    "drive_mgmt": 121,
    "hardware_components": 140,
}
CURSOR_Y_CFG_MGMT = {  # Cfg Mgmt submenu items
    "create_virtual_drive": 70,
    "create_profile_based_vd": 83,
    "clear_configuration": 102,
}
```

### iter 5: clear_configuration() 実装 ⚠️ PARTIAL

scaffolding (Main Menu → Cfg Mgmt → Clear Config → Confirm dialog navigation) は実装。 ただし **Clear Config dialog 内の field cursor detection が不安定**:
- Dialog 内では cursor ► が x=24-26 (menu の x=8-14 と異なる位置)
- 「[Disabled]」文字の "[" 角括弧も bright pixel run を生成 → cursor との誤識別
- `+` キーで Confirm を Enabled に切替えできず

実用上の影響限定的 (NVRAM pending state は trial 間で reset せず累積するが、 form 再 enter で大抵 fresh state)。

### iter 6: WAIT_MS チューニング ✅ SKIPPED

iter 3-4 の WAIT_MS_FAST=700 / WAIT_MS_POPUP=3000 / WAIT_MS_DIALOG=2000 / WAIT_MS_LONG=5000 が安定動作確認、 細かいチューニング不要と判断。 silent drops は nav_cursor_to_y で吸収。

### iter 7: RAID 10 commit 試行 ⚠️ M5 で active-cursor 検出問題

Create VD form open までは PASS。 ただし form 内に **複数の ► マーカーが表示される** (「Save Configuration」TOP と「Select Drives」など 2 か所以上に ► が出る) ため、 `detect_cursor_row` が active cursor (実際の選択行) を正しく識別できず。 ArrowDown が silent drop した際の検出も失敗。

結果: 最初の ArrowDown が dropped (cursor_y は同じ 83 で停止)、 Enter on Save Config TOP は意図せず別 popup を開いて Select Drives From フィールドを [Free Capacity] に変更してしまった。 RAID Level は [RAID0] のまま。

## 未完了 / 次セッション課題

### 1. Create VD form の active-cursor 検出 (最重要)

form 内に「navigable indicator」として複数の ► が表示され、 `detect_cursor_row` が最上位の ► を誤って active cursor と判定。 → 解決案: **行の白背景ハイライト** (highlighted row のテキスト背景が白くなる) を検出。 `detect_active_cursor_row()` を実装する必要あり:

```python
def detect_active_cursor_row(png_path, x_min=30, x_max=200,
                              bg_threshold=200, min_bright_cols=50):
    """Highlighted row 検出: 各 row の bright pixel count (x=30-200)
    が threshold 以上の row が active cursor 行。 多くは 1 行のみ。"""
```

iter 7 で `bright_pixels` count を probe したところ form_open の y=87-94 で bright_pixels=51-65 を検出 (Save Config TOP の highlighted row)。 この approach で全 form items を識別可能。

### 2. Clear Configuration dialog 内 navigation

field cursor detection が不安定。 dialog 内では cursor が異なる X 位置 (24-26)、 そして角括弧文字 "[Disabled]" の "[" が cursor と紛らわしい bright pattern を作る。 → active-cursor 検出 (背景色ベース) で解決可能。

### 3. RAID 10 2-span 自動化 (iter 7-9 の元目標)

active-cursor 検出が安定すれば:
- Select RAID Level → RAID 10 選択 (popup 内の cursor も active-cursor 検出で OK)
- Span 0: 2 drives 個別 toggle (nav_cursor_to_y で drives popup 内の drive 0/1 行に着地)
- Add More Spans
- Span 1: 残り 2 drives Check All
- Save Configuration → Confirm dialog → commit

### 4. dispatcher (`scripts/irmc-bios-raid-setup.sh`) 統合

active-cursor 検出 + RAID 10 commit が動作後、 `cmd_setup_raid10` の S6-S9 を `tmp/iter/_util.py` の関数を呼ぶ inline 実装に置換。 旧コードは `_legacy` リネームで温存。
